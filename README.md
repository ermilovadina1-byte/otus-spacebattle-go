# Космический бой на Go

Локальный сервер одной игры для двух игроков. `alice` и `bob` получают токены, отправляют приказы своим кораблям и читают состояние игры. Приказ чужому кораблю возвращает `403`.

Сейчас сервер выполняет `StartMove`, `Advance` и `StopMove`. `Advance` делает один шаг, автоматического игрового цикла нет. Приказы одной игры исполняет один работник. Снимок состояния проходит через его очередь, поэтому HTTP-обработчик не читает корабль одновременно с его изменением.

## Запуск

Нужен Go 1.27. Из корня репозитория:

```sh
go run ./cmd/battle-demo
```

Сервер слушает `127.0.0.1:8096`. При запуске он печатает `game_id` и временные пароли `alice` и `bob`. После перезапуска создаются новая игра, пароли и ключ; прежние токены перестают действовать.

Получите токен `alice`, подставив выведенные значения:

```sh
curl -u 'alice:<password>' -X POST 'http://127.0.0.1:8096/games/<game-id>/tokens'
```

Скопируйте `access_token` из ответа. Он действует пять минут. Отправьте два приказа и прочитайте состояние:

```sh
curl -X POST 'http://127.0.0.1:8096/commands' \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' \
  -d '{"game_id":"<game-id>","object_id":"ship-alice","operation_id":"StartMove","args":{"initialVelocity":2}}'
curl -X POST 'http://127.0.0.1:8096/commands' \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' \
  -d '{"game_id":"<game-id>","object_id":"ship-alice","operation_id":"Advance","args":{}}'
curl 'http://127.0.0.1:8096/state?game_id=<game-id>' \
  -H 'Authorization: Bearer <token>'
```

Координата `x` корабля `ship-alice` станет равна `2`, `ship-bob` останется на `10`. Токен `bob` для приказа `ship-alice` даст `403`.

## Границы текущей версии

Игра и очередь находятся в памяти. `202 Accepted` подтверждает постановку приказа в очередь, но не его выполнение; статуса конкретного приказа для клиента пока нет. Попадания, победитель и повтор боя также не реализованы. Сервер запускается только локально и не открывает порт во внешнюю сеть.
