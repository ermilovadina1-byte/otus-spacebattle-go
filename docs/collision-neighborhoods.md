# Проверка коллизий через окрестности

`CollisionIndex` выполняет предварительный отбор пар игровых объектов. Каждая система окрестностей делит плоскость на квадратные клетки ширины `w`, со своим смещением. Объект находится в одной клетке каждой системы по текущему положению центра. Для пары из общей клетки индекс создает команду точной проверки, но саму геометрию столкновения не реализует.

```go
offsets := []Vector{{}, {X: 5}, {Y: 5}, {X: 5, Y: 5}}
index, err := NewCollisionIndex(10, offsets, checkCollision, reportCollision)
if err != nil { /* обработать ошибку */ }
err = index.Track("ship-1", ship)
if err != nil { /* обработать ошибку */ }

tick, err := NewMacroCommand(
    Move{Object: ship},
    UpdateNeighborhoods{Index: index, ID: "ship-1"},
    CheckCollisions{Index: index},
)
if err != nil { /* обработать ошибку */ }
err = tick.Execute()
```

`checkCollision` имеет тип `func(CollisionObject, CollisionObject) (bool, error)`, а `reportCollision` - `func(CollisionPair) error`. Передайте туда готовую точную проверку и действие при найденном столкновении. Индекс не предполагает форму, радиус или размер объекта. `Ship` и `Torpedo` уже предоставляют нужный метод `Position()`.

При регистрации `Track` добавляет объект в клетки всех систем. После изменения положения `UpdateNeighborhoods` переносит его из старых клеток в новые. Индекс пересобирает макрокоманды для затронутых объектов: каждая содержит проверки их текущих соседей. `Untrack` удаляет объект и также обновляет соседей. Цепочка обработчиков по числу систем окрестностей добавляет кандидатов, а множество удаляет повторения. Пара хранится в макрокоманде объекта с меньшим ID и проверяется один раз за вызов `RunChecks`.

Если за один игровой шаг перемещается несколько объектов, сначала выполните все `Move` и `UpdateNeighborhoods`, затем один `CheckCollisions`. Так каждый предикат увидит положения одного и того же шага. Все операции индекса должны исполняться последовательно на одном игровом работнике; индекс и сами объекты не защищены для одновременного изменения несколькими работниками.

Предикат и обработчик найденного столкновения не должны менять положения или состав индекса во время `RunChecks`. Такие эффекты сначала запишите как команды и примените после завершения прохода, затем обновите окрестности перед следующей проверкой.

## Границы корректности

Две системы со сдвигами `(0,0)` и `(w/2,w/2)` не покрывают все близкие пары в 2D: пара может пересекать границу X в первой сетке и границу Y во второй. Четыре сочетания сдвигов `(0,0)`, `(w/2,0)`, `(0,w/2)`, `(w/2,w/2)` гарантируют общую клетку для центров, чье расстояние строго меньше `w/2` по каждой оси. Более широкий объект может столкнуться с другим и при большем расстоянии центров. Без верхней границы размеров или охвата соседних клеток полноту отбора гарантировать нельзя.

Проверка выполняется для текущих положений, а не для всего пути между двумя игровыми шагами. Быстрый объект может пролететь через другой между шагами; для непрерывных столкновений нужна отдельная геометрия. Макрокоманда останавливается на первой ошибке предиката или отчета, поэтому уже сообщенные столкновения не откатываются. При ошибке чтения положения или переполнении номера клетки обновление членства не начинается.

Если объекты распределены по клеткам с числом объектов `k`, количество точных проверок ограничено числом уникальных пар, появившихся в клетках. Для редких клеток это меньше полного перебора `n(n-1)/2`; в одной плотной клетке остается квадратичная стоимость. После любого перемещения нужна команда обновления окрестности, иначе индекс будет использовать старую клетку.
