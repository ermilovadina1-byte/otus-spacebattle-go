# Режимы обработки команд

`CommandWorker` выполняет команды в одной горутине. После извлечения каждой команды текущий режим возвращает режим для следующей. Начальный режим - обычный.

| Текущий режим | Команда | Действие и следующий режим |
| --- | --- | --- |
| Обычный | Обычная | Выполнить здесь, остаться в обычном |
| Обычный | `MoveToCommand{Target: other}` | Перейти в MoveTo для очереди `other` |
| MoveTo | Обычная | Передать в очередь `other`, остаться в MoveTo |
| MoveTo | `MoveToCommand{Target: third}` | Переключить целевую очередь на `third` |
| MoveTo | `RunCommand{}` | Вернуться к выполнению здесь |
| Любой | `HardStopWorker{Worker: current}` | Завершить работу и отбросить ожидающие команды |
| Любой | `SoftStopWorker{Worker: current}` | Закрыть прием, обработать ранее принятые команды |

`MoveToCommand` отвергает пустой целевой работник и перенаправление в себя. Неудачное перенаправление в закрытый работник записывается в `Failures`; команда локально не выполняется. `RunCommand` возвращает обычный режим даже после такого отказа.

`SoftStop` исходного работника гарантирует обработку его принятых команд в текущем режиме. В MoveTo это передача в другую очередь, а не подтверждение выполнения целевым работником. Для целевой очереди действуют ее собственные правила `HardStop` и `SoftStop`. `Done` относится только к тому работнику, у которого вызван.

Маршруты между работниками должны быть без циклов. Если два работника направляют команды друг другу, команда будет пересылаться без завершения; автоматического обнаружения такого маршрута пока нет.

Команды `MoveToCommand` и `RunCommand` нужно ставить в очередь `CommandWorker`; их прямой вызов `Execute` возвращает `ErrModeCommandNotQueued`. Цикл работника зависит только от `workerState`, а не от типов обычного режима и MoveTo.
